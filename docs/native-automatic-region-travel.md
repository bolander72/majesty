# Automatic native region lifecycle

The later [request-driven trial](native-request-region-travel.md) removes the
fixed twenty-tick trigger and qualifies deliberate travel plus stale/replay
refusals. The results below describe the earlier exact093 timed prototype.

Native093 removes menu input from the committed two-kingdom residency trial.
One native process automatically restores home, remote, home and remote,
using the existing original named checkpoint loader and context attachment.
The four initial/return loads, full saves, original simulation and teardown
qualify independently. This is engine lifecycle routing, not spatial hero
crossing, an arbitrary expanding world or cooperative region activation.
Browser testing remains suspended under the unresolved app-crash constraint.

## Transition and original engine ownership

The native-only `BROWSER_STREAMING_AUTO_REGION_LOAD_FIXTURE=v1` requires the
owned connected-residency profile, registered-hero load order and original
persistence. Fresh generated initialization and TILE-release trials refuse.
Its entry runs at original front-end00490fc0 after dispatcher disposal.
The previous world must be null, phase1 current, visit/load/exit/accepted counts
consistent, zero hook depth and the scheduler baton held. Subsequent entries
also require the preceding saved clock. At the final configured exit the
normal menu remains available.

`majesty_browser_frontier_residency_restore` delegates to the already verified
`restore_checkpoint` with `Joint_Reload`. Original00435940 dispatches named
serialization, original manager attachment accepts the context, and
original00415f30 creates/attaches the active world and requests phase2.
The outer dispatcher rebuilds its normal gameplay interfaces. The adapter
completes the original menu's thiscall RET4 exactly as the existing automatic
checkpoint path. It does not simulate menu clicks or retain the old world.

Each region runs20 complete ticks. The existing original writer publishes its
latest evolving save, queues the original exit, and verifies six world roots
freed once. The next source is copied with the existing bounded4KiB file helper;
the next empty-world boundary restores it automatically. The original loader
owns full graph reconstruction, including buildings, units, scripts, queues,
terrain and saved RNG restoration. Emulated pointer centering comes from the
existing automatic loader and does not move the physical mouse.

## Resources and limitations

Native process43423 exits0 with no stop reason after31,305ms. Maximum sampled
RSS is182,484,992 bytes (174.03125MiB), below the unchanged512MiB ceiling.
The owned runner has a45-second duration ceiling. A single official one-job
smoke build093 runs; no generated translation is edited and no browser/WASM
build, staging or launch occurs. The exact093 executable, native sources and
symbols are preserved/synced with4KiB transfers and registered. Original settings,
selected kingdoms, publication and receipt remain unchanged.

No speed or total-memory reduction is claimed from different test timing.
Ordinary requested heap bytes still grow407,248 between home visits0→2 and
230,592 between remote visits1→3, including the previously observed once-
appearing229376-byte group. Automatic boot skips normal menu activity, so its
heap baseline differs from menu-driven trials; do not equate those totals.
Sustained native/browser resource limits and arbitrary queue/message coverage
remain unqualified. The flag is explicitly unavailable in Emscripten and is not
a browser/co-op feature switch.
