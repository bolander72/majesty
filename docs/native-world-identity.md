# Original world identities and natural script backlinks

Destination attempt 024 qualifies 64 original identity publications and registry
retirements across four copied Brashnard war-follower NPCs in Scions. These are
player-seven NPC fixtures, not a general hero migration implementation. The goal
remains active; no browser was opened and no served WASM was rebuilt.

## Result

Each grounded private actor retains its three populated command banks while an
original constructor reserves a fresh script ID. Its existing EA scalar points
to that script through a temporary original script ID-tree entry. Original
005a12e0 then publishes a fresh native ID into the destination registries, and
original 006263b0 assigns that ID to the script. The script cached pointer starts
at zero. Original 00626310 resolves the exact actor through the actual native
registry; the test does not inject a cached pointer to make lookup succeed.

Four registration/retirement warmups precede the steady cases. Native IDs increase
from counter 508 to 576 across all 68 reservations without rewind. Script IDs
79 through 142 identify the 64 joint cases. All 192 actual original UNIT, GPL and
command writer files independently match the complete expected transformations.
The UNIT and GPL native IDs agree, both script self references use the fresh
script ID, and both external leader references resolve to actual agent 2. Ground,
command/script ages, approach goals and complete original routes remain qualified.
The existing 64 saved-file command replays also pass; they do not replay the joint
UNIT/GPL association.

Before draining commands, the test restores the EA, clears the original script
cached/native association and removes the native actor through original 005baf20.
That function erases registry membership before invoking the deleting destructor.
A temporary exact-owner hook defers only that destructor, under the matching
original guarded-call cookie, return PC and deleting argument, so checked command
cleanup can still use its owned actor. The hook is removed immediately. Lookup
must return zero and all 17 registry groups must recover their prior logical list
ID/pointer membership, list/tree counts, addresses and tables. Exact tree shape
or an independent comparison of every tree entry is not claimed. Only then are the owned object's native ID/world publication tags reset.
The script ID entry and original script storage are retired, commands drained,
and the original actor destructor finally runs. Heap requested/used bytes and
blocks, GPL/CRT pool occupancy, hooks, queues, leader header, clocks, secondary
counter and grid baselines recover. Native/script identity counters intentionally
advance. No movement, script execution, spatial insertion or rendering is enabled.

## Original orders marker

Attempt 023 identified one native header change: UNIT+0x40 changed from zero to
one. The pinned executable explains this in original ORDR registry filter
005f2920, table 0068b6f0 slot +0x0c. It invokes UNIT slot +0x194 (005b2b50), which
checks the three nonempty command banks through slots +0x190 and +0x16c. On success
it ORs bit one into UNIT+0x40. Registration dispatch calls this filter before
inserting registry membership. Twenty-five pinned instruction anchors and seven
vtable slots cover the identity, retirement, filter and bank-query boundaries.

The fixture now requires the actual ORDR group, an original nonempty-bank query,
and exactly this zero-to-one transition in every joint case. The bit remains set
after original registry retirement and through command cleanup until owned actor
destruction. It is never raw-restored. Header comparison permits only this audited
original derived change; every other header byte still must match the restored
baseline. This is not evidence of complete live alias closure or full linked
storage preservation.
