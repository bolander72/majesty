# Travel through ordinary named controls

The native smoke host can admit a gate and selected operation together with
`actions FIRST SECOND`. Both names enter the fixed request store under one
mutex, or neither enters when there is insufficient space. Existing pending
names keep their original expiry. Consumption remains one boolean at a time
on the game thread; admission is atomic, consumption is not a transaction.
The ordinary single-name command remains unchanged.

Majesty's travel handler polls `frontier-travel`, then the four direction
names. Delivering the gate and direction in separate host turns could let
the game consume the gate too early. The paired command follows the browser
control's existing two-name protocol without changing that protocol or the
game's save/dispose/load implementation.

## Native qualification route

`scripts/run-native-region-session.py --named-travel` uses the owned native
profile and existing one-process guard, but removes
`BROWSER_FRONTIER_SESSION_REQUEST_FIXTURE` from the child environment.
It never publishes Session_Request.txt. A bounded script sends two genuine UI
requests toward the refused orphan/symlink neighbors, then two to four real
cardinal trips and a final ordinary checkpoint. Inputs are spaced by at least
three seconds, beyond the one-second expiry, so stale directions cannot be
merged with a later gate. The final checkpoint uses the ordinary handler and
does not manufacture the test fixture's terminal direction4/serial.

The controller observes original checkpoint, release, world-null, observer
retirement and attachment messages, copies departure saves and retains a
separate final checkpoint. It requires the exact requested route, all eight
tracked original roots freed per departure, saved-mode home return, ordered
events and a successful final original checkpoint. A queued request alone
does not count as a completed trip. Deadline, sampled RSS, private registry,
original input preservation and executable guards remain in force.

## Limits

This is a discrete regional-world prototype. It does not migrate heroes,
inventory, guilds or orders across the boundary, or establish seamless travel
across one continuous map. Those remain separate integration work. The native
experiment does not qualify browser memory, co-op world activation or an
independent internet match. Browser launches remain suspended, and the latest
two-player test still needs a human exception to the one-heavy-process rule.
